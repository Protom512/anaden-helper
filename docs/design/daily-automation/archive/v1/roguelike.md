# roguelike — メビウスの迷宮 pipeline 設計

ステータス: 設計 v1。実装前。**エピック** — 現行エンジンにない能力 (ランダムマップ探索制御) が必要。優先順 4 番 (最後)。

## 1. コンテンツ仕様 (wiki 調査結果)

- 解放: 外史「彷徨える少女と久遠の渦」プロローグクリア。
- **入場料なし (カードキー不消費)** — 日次回数制限なし。周回上限は実質プレイ時間。
- 毎回: ダンジョン内エリアが**ランダム生成**。装備なし・Lv1 スタート。道中の「ルーン」(スキル/アビリティ) で強化。
- 構造: 20 層。**4 層毎 (4/8/12/16/20) に階層ボス** (各層 2 種から選択):

| 層 | ボス A | ボス B |
|---|---|---|
| 4 | 大きなアベトス | キマイラ |
| 8 | ペグマタイラント | ライストリーマ |
| 12 | クラーケン | ヒュドラ |
| 16 | ゴブキング | 赫き黎明 |
| 20 | 次元の歪み | — |

- 報酬: ボス撃破で**オーパーツ** → 迷宮の村アララトで鑑定 (装備化)。4 層ボスフロアでルーン 1 つ**登録** (次回持ち越し)。
- 持ち込み: **チャーム 3 つ**。4 層高速周回の定番 = 超転生のチャーム (初期 Lv10) + 豪腕Ⅲ (腕力+30%) + 虚空Ⅲ (無属性物理+30%) — 初期ルーン火力ゴリ押し。
- 探索要素 (自動化でハンドルが必要なもの):
  - **同フロア長時間滞在で強敵襲来** (ソフトタイマー)
  - **罠**: HP20%ダメージ / 強敵接近 / 同階層別エリアへワープ / 所持アイテム消失。回避 = MP10 消費 or 時のお守り
  - **キラキラ**: 聖水 (MP10/20%) / 薬草 (HP10/20%) / 宝箱の鍵 / 千里眼のオーブ (現階層マップ構造把握) / 活力のオーブ / 減衰のオーブ / 時のお守り / 割引券 / 仕入れ直し券 / オーブ (Lv+3) / 魔除けの聖水 / 地図
  - **ルーンショップ** (通貨: アルカナフレア、割引券+仕入れ直し券で買占め)
  - **逃亡者**: 一定ターンで逃走・開幕 AF 発動で確定撃破 (大量 EXP + アルカナフレア)
  - **アンモナイト** (9 層〜): ターン経過でルーン生成、さらに経過で高レアリティ
- ノクシス加入: 4 階層毎ボスの一定数討伐 (低層ボスほど早い。攻略班実績: 20F 3 回踏破)。
- 成長タイプ 5 種 (攻撃/防御/技巧/支援/魔攻) — 同タイプならステータス同一 → **自動化では編成を固定してよい**。
- 時短テク: 5〜7 層はワープ直行、7F ボス前の選択肢で脱出すると時の鋳貨 255。

## 2. 目標サイクル (4 層高速周回)

```
[アララト入口] → [編成確認 (固定)] → [チャーム確認 (超転生/豪腕Ⅲ/虚空Ⅲ)]
→ [入場] → [1〜4層: ランダムエリア探索 (遇敵はオート)] → [4層ボス (アベトス or キマイラ)]
→ [ボス撃破 → 選択肢] → 脱出 → [リザルト/オーパーツ] → [アララト] → loop
```

## 3. 状態機械 (固定部分)

```
[ararat_hub] →(入口)→ [party_confirm] →(問題なし)→ [charm_confirm] →(入場)→ [floor_load]
[floor_load] →(階層バナー floor_banner_N 検出)→ [area_explore]
[area_explore] … ランダム。§4 の探索制御。
  ├─ encounter → [battle_auto] → battle_end → [area_explore]
  ├─ rune_shop dialog → 設定ポリシー (基本は閉じて進む / アルカナ余剰なら購入)
  ├─ trap dialog → 「MP10 で回避」を選択 (時のお守り優先)
  ├─ キラキラ → タップして取得 (優先度: 地図/千里眼 > 聖水/薬草 > その他)
  ├─ 逃亡者 → 開幕 AF 発動タップ
  └─ 次エリア移動点 → 進む
[boss_floor] →(ボス選択)→ [battle_auto (AF あり)] → [boss_result]
  ├─ 4層ボス後の選択肢 → 「脱出」→ [escape_result] → [ararat_hub]
  └─ (将来) 20F 踏破モード → 続行
```

## 4. 新要求能力 (現行エンジンのギャップ)

1. **ランダムマップ探索制御**: 未訪問方向の記憶 + バックトラック。
   - 案 (b) 最小版: ミニマップ差分ベースの訪問済み判定 + 未探索方向を順に試すヒューリスティック。ワープ/コンパス (千里眼・地図でマップ構造把握) を優先利用。
   - 千里眼のオーブ/地図は「現階層のマップ構造を把握」するアイテム = **UI 上にマップ全体が表示される** → これを検出してワープ地点へ直行するのが最も決定的。優先して取得・使用する設計。
2. **ターン経過待ち** (アンモナイト): 戦闘中に「防御し続けてターンを経過させる」待機ポリシー。(初版ではアンモナイト処理は省く — 9 層以降のみ出現のため 4 層周回には不要)
3. **in-run 内部状態モデル**: 最小版は「現層数 + 所持キラキラ数」のみで意思決定。ルーン/チャーム詳細のモデル化は将来。

## 5. フェーズ分割 (過大約束しない)

- **(a) 実機計測** (最初にやる): 1〜4 層のランダム性の度合いを実測 (エリア数・分岐数・ワープ出現率)。**4 層直行の半固定ルートが成立するか**を確認。
- **(b) 最小実装**: 探索 = ミニマップ未探索方向ヒューリスティック。チャーム固定・ルーンショップ素通り・罠は MP 回避・逃亡者は AF。4 層ボス → 脱出を 1 サイクルとし LoopCount で N 周回。
- **(c) 将来拡張** (明示的に本設計のスコープ外): 完全探索制御、20F 踏破、アンモナイト高レアリティルーン生成、ルーン厳選。

## 7. 受け入れ基準 (フェーズ b)

- 4 層 1 サイクルを 3 連続で完走 (強敵襲来・罠・逃亡者のいずれかを最低 1 回ずつ踏んで正常処理)
- 1 サイクル所要時間の実測値を report に記録 (目安: 手動 5〜10 分)
- 証跡: run.log + report.json を Issue に添付

## 8. リスク

- ランダム生成の多様性が想定を超え (b) のヒューリスティックが破綻する可能性 → (a) の実測で判断、破綻時は (c) に昇格 or 半自動 (探索のみ人間) に降格 — いずれも Issue で意思決定を記録してから。
- 戦闘の長期化 (火力不足) → チャーム/ルーン前提を冒頭の前提条件チェックで担保。
