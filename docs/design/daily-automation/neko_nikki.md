# neko_nikki — ねこにっき pipeline 設計

ステータス: 設計 v1。実装前。優先順 2 番。

## 1. コンテンツ仕様 (wiki 調査結果)

- 解放: メイン 25 章クリア後、次元の狭間で解放イベント。
- 日記の確認: **メニュー (画面左下) → Diary**。日記は毎日 0 時に更新。
- 枠数: 2 部 (84章) クリアで **3 枠**。
- ループ: ヒント (固定文 **73 種**) → 当該エリアへ移動 → マップに Diary アイコン (羽根ペン) → 現地の猫をタップ → ランダム報酬 → **確率で猫がさらに別の場所へ移動** (日記の猫に足跡マークが付かなければ新ヒントで再捜索、報酬は加算されて豪華になる)。
- ランダム報酬: クロノスの石×200 / ねこの手特急券×6 / ステータスバッジ / レッド・キー×2 / 囁きの書×2 / 中級・上級秘伝巻子 / グラスタの欠片 (50/60/100) 等。
- スタンプ: 猫発見ごとに確定 +1。**6 個毎にオスソワ毛玉** → 次元の狭間上部のタル → ネコの皿で女王猫装備 (経験値 UP 武具、全 16 Lv) と交換。スタンプ数は**毎週火曜 0 時リセット**。
- にっきレベル: 発見回数 + ストーリー進行で上昇 → 猫の行き先増 / 散歩猫増 / スタンプ上限増。

## 4. ヒント読み取り設計 (OCR 不要の根拠)

ヒント文は**全 73 種の固定文** (下表) であり、ゲーム更新で追加されない限り変化しない。よって:

- ヒント表示領域を ROI 固定し、73 個の**文字列テンプレート** (スクリーンショットからヒント冒頭 1 行目を crop) との CCOEFF 照合。
- 未知ヒント (追加コンテンツ) は NoMatch → **fail-closed**: その枠を skip して report に記録、pipeline は継続。
- テンプレート収集は「その日のヒントを見た時に collector で貯める」運用 + 未収集分は wiki 文言から手作業で crop 種付け。73 種の網羅は data ファイルの `template_status` フラグで管理。

## 5. エリア内歩行ナビ (本 pipeline 最大の難所)

- 方式: **ミニマップ/フィールド上の羽根マーカー追従**。毎 tick `feather_marker` を検出し、マーカーの画面座標方向へタップ移動。カメラはキャラクター追従前提。
- 到達判定: `cat_sprite` (猫スプライト) の検出。
- 画面外マーカー: マーカーの最後既知方向の画面端をタップして前進 → 再検出のループ。タイムアウト (60s/エリア) で fail-closed + 診断スクショ。
- 要実機検証: PC 版ミニマップの有無・羽根マーカーの描画位置。検証結果次第で「ミニマップ追従」or「エリア固定ルート (入口→猫出現座標テーブル)」に分岐。エリアによって猫の出現位置が複数ある場合は座標テーブルを充填する方式が頑健。

### data/nav_routes.toml

`次元の狭間 (または直前訪問地) → era_tab → 大陸 → 地方 → エリア` の world map 操作列 (スクロール位置込み) をエリア毎に 1 エントリ。Phase 1 は実際にヒントで訪れる頻度の高い代表エリア (バルオキー/月影の森/ユニガン/ミグランス城/ラトル/エルジオン/ガルレア 3 領/冥峡界) から充填し、未充填エリアは fail-closed skip。

## 7. pipeline 実装メモ

- 配置: `templates/pipelines/neko_nikki/`。task 数は「共通 (menu/diary/nav)」+「エリア別 nav route」+「ヒントテンプレート照合タスク群」。
- ヒント照合は 73 タスクを ROI 同一で並べ、マッチしたものが current になる方式 (現行 `advance_next` モデル内で表現可能: diary 画面にいる間、次候補に hint task 群を並べる)。
- goal: `Any{ All{TemplateMatch(diary_all_pawmark)}, Timeout(1800) }` (3 枠全て足跡 = 完了)。
- 再移動ループ上限: 3 回/枠。超えたら report に記録して次枠。

## 8. 受け入れ基準

- 3 枠 × 連続 3 日完了 (再移動分岐を含めて全枠足跡)
- 未知ヒント / 未開放エリアで pipeline が停止せず skip & 報告すること
- 証跡: run.log + report.json (生コマンド出力) を Issue に添付
